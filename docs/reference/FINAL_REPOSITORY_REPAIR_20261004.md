# Final Repository Repair — 2026-10-04

## Purpose

This release repairs the Windows setup failures reported during the first clean installation and hardens the repository against foreseeable toolchain, TypeScript, accessibility, dependency, and analytical-truth failures.

## User-reported failure addressed

The Windows run reached the approved Node/npm/Python environment and successfully installed the pinned Python stack. Data verification passed. The analytical truth gate then failed because it compared a future Holt-Winters forecast to an exact value generated by an older statsmodels release. The January 2027 point forecast differed between statsmodels versions while the model contract remained valid.

The truth gate now deliberately does not freeze future point forecasts to a single library patch release. It verifies the forecast structure, horizon, chronological validation advantage over the seasonal-naive baseline, finite/non-negative outputs, uncertainty-band nesting, model identity and uncertainty method.

## Frontend quality repairs

- Biome 2.5 configuration uses `files.includes` and `linter.rules.preset`.
- Accessibility checks avoid unsupported `aria-label` usage on generic containers.
- Loading skeleton keys are stable and not array indexes.
- Application TypeScript contains no explicit `any` or suppression directives.
- React effects do not synchronously reset state.
- API requests are abortable and filter dependencies are stable.
- ECharts callback typing is kept compatible with the library's broader callback values.
- TanStack Table v9 uses the current typed `createColumnHelper` / `useTable` model.

## Setup hardening

`setup.bat` calls `scripts/setup.ps1`. The PowerShell bootstrap:

1. verifies Node 24.21.x and npm 11.19.x;
2. verifies Python 3.13.x;
3. prepares root and backend environment files;
4. repairs/recreates the backend venv when its Python version is wrong;
5. installs the exact Python dependency lock;
6. checks pip consistency;
7. self-heals a stale npm lockfile when direct dependencies no longer match `package.json`;
8. installs frontend dependencies;
9. runs repository, data, analytical, Python, formatting and frontend quality gates;
10. builds Next.js;
11. audits production dependencies;
12. starts FastAPI and Next.js only when their ports are available;
13. verifies both services over HTTP;
14. records timestamped logs;
15. cleans up only processes started by this setup run if startup fails.

## Reproducibility note

The final package intentionally does not include `node_modules`, `.next`, Python virtual environments, caches or generated logs. The first clean install under Node 24/npm 11 creates `package-lock.json` from the pinned `package.json`. Subsequent setup runs use `npm ci` when the lockfile matches the direct dependency contract.

## Verified source of truth

The supplied Superstore workbook remains authoritative. No dataset replacement or hardcoded dashboard values are introduced.
